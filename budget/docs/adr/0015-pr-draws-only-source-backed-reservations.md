# A ใบขอซื้อ draws only source-backed reservations

A ใบขอซื้อ (พ.1) may spend a `budget.commitment` only when that commitment belongs to a **โครงการ/กิจกรรม** (`kmitl.project`) or a **แผนจัดซื้อจัดจ้าง** (`procurement.plan`) — never a standalone ใบจองงบประมาณ, because money reserved with no plan or project behind it does not satisfy **ระเบียบการจัดซื้อจัดจ้าง**: procurement must trace back to an approved procurement plan or project. The พ.1's budget question therefore has a **closed set of three answers** — ผังงบประมาณ (reserve anew), โครงการ/กิจกรรม, แผนจัดซื้อจัดจ้าง — each owned by the module that owns the source, and the standalone draw-down that [ADR-0010](./0010-standalone-reservation-picked-drawdown.md) gave every consuming document is **withdrawn for `purchase.request` only**. `approval.request` keeps it: a คำขออนุมัติ is how non-procurement spending reaches a source-less slip, so the two consuming documents differ **by design**, not by oversight.

## Considered Options

- **Keep the standalone mode and rely on reviewers to reject non-compliant พ.1** — rejected: the rule is regulatory, not a matter of judgement, and the reviewer sees the slip only after the request is written.
- **Let the source-less slip declare which documents may draw it** (a flag on `budget.commitment`) — rejected: eligibility is a property of the *consuming* document's regulations, not of the money. The same slip is legitimately spendable by a คำขออนุมัติ and illegitimately by a พ.1; a flag on the slip cannot express that.
- **Ask the source question only as a filter inside one "หยิบใบจอง" mode** — rejected: it splits one decision the officer makes once into two controls, and ADR-0010 introduced the radio precisely because side-by-side pickers hid the fact that the options are alternatives.

## Consequences

- **The regulation lives in `_check_drawable_commitment`, not in the view.** The base `purchase.request` implementation now raises unconditionally; each bridge's override is the only way through. `budget_selection_mode` stays a **UI affordance only** (ADR-0010) — the server never reads it, so a slip injected through a context default or RPC is rejected by the same gate as one picked in the dropdown.
- **`purchase_request_budget` alone has no draw-down capability.** Installed without `kmitl_project_purchase_request` or `purchase_request_procurement_plan`, a พ.1 can only reserve anew. This is intended: with no source module installed there is no compliant source to draw from.
- **Source-side eligibility belongs in the picker domain**, following ADR-0010's precedent that the picker excludes plan slips that already have an active PR: the project mode requires `kmitl_project_id.state = in_progress` (the approval gate of [kmitl_project ADR-0005](../../../kmitl_project/docs/adr/0005-approval-gated-lifecycle-esaraban.md)) and the plan mode requires `procurement_plan_id.state = verified` (which also expresses ADR-0006's one-active-PR rule, since drawing moves the plan to `in_progress`). Amount caps stay server-side at draw time — they are computed, not queryable — and there they can tell the user the remaining headroom, which a slip missing from a dropdown cannot.
- **ดึงกลับ (Reset) does not reopen the budget source.** A recalled project/plan พ.1 keeps its shared commitment (recall is for editing the request, not for giving the source's budget back — release happens only on ยกเลิก), but the source itself is not re-selectable: a project and a plan each hold exactly one active commitment, so "re-pick within the same source" is a no-op and the only thing a reopened picker could do is silently migrate the request to a *different* project or plan — leaving the old plan stranded at `in_progress` with no PR and shifting both sources' headroom. Moving a พ.1 between sources is a cancel-and-recreate, not an edit.
- **Terminology.** The radio is the **แหล่งงบประมาณ** (source) of the request, not the *วิธี* (method) of choosing it; the ผังงบประมาณ answer is labelled "จองงบใหม่จากผังงบประมาณ" rather than with the word "แผน", which `budget/CONTEXT.md` already spends on แผนงาน (the `activities` level), the โครงการ/แผน pool tag, and ปรับเข้าแผน.
