# ลงทะเบียน runs at completion (final ลงนาม/อนุมัติ), not at send

**Supersedes the numbering timing in [ADR-0002](./0002-document-lifecycle-negative-paths.md) and [ADR-0006](./0006-recall-split-pullback-vs-cancel-send.md).** ADR-0002 (and the DESIGN §4 "Register event") fixed ลงทะเบียน to fire **automatically at send** (`draft → circulating`): the official number was allocated the moment the หนังสือ left the sender, then **voided** as a permanent register gap if the Document was later rejected (ปฏิเสธ) or cancelled (ยกเลิกการส่ง). In practice this floods the register with voided gaps for every หนังสือ that does not survive its route, and — more fundamentally — assigns an official number to a document that has **not yet been approved by anyone**.

KMITL's requirement: **the official number must run only when the หนังสือ receives the signature/approval of the *final* authority.** While the หนังสือ travels its approval route it has **no number** (ที่ = `/`).

We therefore **move the ลงทะเบียน seam from send to completion**:

- `action_send()` no longer allocates. It keeps the fail-fast guard — it calls `_resolve_sequence()` so a unit with **no register** is still blocked at send with a clear error (a route must never be able to reach its final signature only to strand there with no number to allocate) — but it does **not** consume a counter.
- `_complete_document()` calls `_assign_register_number()` **before** `_freeze_signed_copy()`, so the number runs exactly once, at the instant the last gating step is positively done, and the frozen official PDF carries it.

## Consequences

- **A circulating หนังสือ is unnumbered.** `name` stays `/` (rendered as "New") through `draft → circulating`; it is set only on the `→ completed` transition. Source-document reports that echo `active_sarabun_document_id.name` (purchase_request_sarabun, agx_approval_sarabun, purchase_request_approval) therefore show no number until the หนังสือ is fully signed — which is the intended behaviour, not a regression.
- **Voided numbers (เลขยกเลิก) effectively disappear from the normal path.** Reject (ปฏิเสธ) and cancel-send (ยกเลิกการส่ง) are both pre-completion, so there is no number to void — `_void_register` becomes a guarded no-op there. A rejected/cancelled หนังสือ **consumes no counter**, so the register no longer accumulates gaps for abandoned documents. `_void_register` and the `voided` ledger state are **retained** (belt-and-braces + the reserved/manual compose paths), but the *Voided number* concept is now largely historical for `from_record`. The counter series is contiguous over *completed* documents, in completion order.
- **ADR-0006's number-keep-vs-void distinction is subsumed.** ดึงกลับ (pull-back) was defined as "keep the number, re-send" and ยกเลิกการส่ง as "void the number, terminal". With no number assigned while circulating, the numbering no longer distinguishes them — the difference is now purely **pull-back-to-edit-and-re-send** (`→ returned`) vs **terminal cancel** (`→ cancelled`). The signature guard (both blocked once a ลงนาม-อนุมัติ step has occurred — ADR-0002) is unchanged, and remains keyed on `has_signed`/strongest-verb, never on the number.
- **Idempotency still holds.** `_assign_register_number()` is guarded on `register_number_id`, so a `returned`-then-re-sent-then-completed หนังสือ is numbered once, at its (single) completion.
- **Document date (ลงวันที่) & fiscal year.** `date` is stamped at **send** (the issue moment), not at create — a draft prepared near ปีงบประมาณ year-end carries the *new* year's date when it is actually sent (the common "draft ahead, send in the new year" case). The number's ปีงบ is taken from the **completion** moment (`allocate` uses the registration date). These always coincide because, operationally, a หนังสือ **never straddles a fiscal-year boundary** — so ที่ and ลงวันที่ are guaranteed to be in the same ปีงบ without keying the number off `date`. `date` remains owner-adjustable in a later phase.
- **Register order = completion order.** Because the number is drawn at completion, the counter series runs in order of *final approval*, not order of submission: a หนังสือ sent earlier but approved later gets a *higher* number than one sent later but approved first. This is inherent to numbering-at-completion and is the intended, regulation-aligned behaviour (the number marks when the หนังสือ became official).
- **Late-failure surface for manual compose.** For `reserved`/`gap`/`manual` numbering (phase-2 manual compose only; `from_record` is always `auto`), the reserved-number / counter validation now runs at completion rather than send. `from_record` (the v1 focus) resolves its register at send via `_resolve_sequence()`, so it cannot fail late. Tightening manual-mode validation to also pre-check at send is deferred until manual compose ships.
