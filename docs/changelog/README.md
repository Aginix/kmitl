# Changelog

บันทึกการเปลี่ยนแปลงของระบบในแต่ละวันที่ deploy

สร้างด้วย Claude ได้ผ่าน skill `changelog` (`.agents/skills/changelog/`) เช่น "ช่วยสรุป
changelog ตั้งแต่ commit `<sha>`"

## กติกา

- **หนึ่งไฟล์ต่อหนึ่งวัน** ตั้งชื่อเป็นวันที่แบบ พ.ศ. `YYYY-MM-DD.md` เช่น
  `2569-10-14.md`
- **deploy หลายรอบในวันเดียว** ให้เพิ่มเนื้อหาต่อในไฟล์ของวันนั้น ไม่ต้องสร้างไฟล์ใหม่
- **rollback หรือแก้สิ่งที่ประกาศไปแล้ว** ให้แก้เนื้อหาเดิมในไฟล์ตรงๆ ไม่ต้องต่อท้าย
  ผู้ใช้จะได้ไม่เห็นข้อมูลที่ขัดกันเอง

## โครงสร้างไฟล์

แต่ละไฟล์มี 2 ส่วน สำหรับผู้อ่าน 2 กลุ่ม

1. **ส่วนบน — สำหรับผู้ใช้** (ส่วนที่เผยแพร่)
   - จัดกลุ่มตามงานของผู้ใช้ เช่น งบประมาณ, โครงการ/กิจกรรม, แผนจัดซื้อจัดจ้าง
   - ใช้ป้าย **ใหม่** / **ปรับปรุง** / **แก้ไข**
   - เขียนเป็นภาษาผู้ใช้ ไม่มีชื่อ module, field, เลข PR หรือศัพท์เทคนิค
2. **ส่วนล่าง — สำหรับผู้ดูแลระบบ** (หัวข้อ `## สำหรับผู้ดูแลระบบ`, ตัดออกก่อนเผยแพร่)
   - แยกเป็นรอบ deploy แต่ละรอบระบุช่วง commit (`<จาก>..<ถึง>`)
   - module ใหม่ที่ต้องติดตั้งด้วย `-i` (`-u` ไม่ติดตั้ง module ใหม่ให้ แม้จะเป็น
     `auto_install`)
   - migration และขั้นตอนที่ต้องทำก่อนหรือหลัง deploy
   - เวอร์ชัน module ที่เปลี่ยน
